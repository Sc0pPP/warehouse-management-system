# Складская система (курсовая)

Десктопное приложение для управления складом и товарными запасами.
Стек: **React** (фронт) + **C#/ASP.NET Core** (бэк) + **Avalonia UI** (десктоп-оболочка) + **PostgreSQL** (БД).

Разделение работы: бэкенд и Avalonia-оболочку пишет автор проекта; фронтенд, связку фронт↔бэк и деплой — Claude.

## Структура репозитория

```
Kursach/
├── database/     — SQL-схема и тестовые данные (готово, накатано в локальный Postgres)
├── frontend/     — React-приложение (черновик, реальный код, уже запускается)
├── backend/      — сюда ляжет C#/ASP.NET Core проект (пока пусто — твоя часть)
├── docs/         — контракт API и прочая документация для стыковки фронта с бэком
├── design/       — экспорт UI-мокапов (чертёжный/индустриальный стиль), взят за основу фронта
└── .claude/      — launch.json для запуска дев-сервера фронта через превью-инструмент
```

### `database/`

- **`01_schema.sql`** — DDL: 11 таблиц (справочники `roles`/`counterparty_types`/`document_types`, каталог `categories`/`products`, склады `warehouses`/`stock`, `users`, `counterparties`, документы `documents`/`document_items`). Все FK, CHECK-констрейнты (остаток не может быть отрицательным, `target_warehouse_id ≠ warehouse_id` и т.д.), индексы по внешним ключам.
- **`02_seed.sql`** — тестовые данные. Номенклатура, поставщики, покупатели и пользователи взяты из твоих UI-мокапов (`design/`), чтобы фронт-заглушки и реальная БД показывали одни и те же значения — так сразу видно, совпадает ли то, что рисует фронт, с тем, что лежит в базе.
- **`README.md`** — как поднять/пересоздать БД, строка подключения, и важное архитектурное решение: `stock` — это кэш остатков, который меняется **только** через проведение документов, а не редактируется напрямую.

БД уже создана и заполнена локально (`warehouse_db`, проверено через `psql`).

### `frontend/`

Реальный Vite + React проект (обычный JS, без TypeScript — как договаривались). Уже запускается (`npm run dev`) и визуально повторяет чертёжный стиль мокапов (шрифты Barlow/Barlow Condensed, засечки по углам карточек, акцент `#5980a6`).

```
frontend/src/
├── styles/design-system.css  — дизайн-токены и компоненты (.card, .btn, .tag, .table…),
│                                скопированы из твоих мокапов (design/ds/styles.css) —
│                                отсюда визуальное 1:1 совпадение с прототипом
├── index.css                  — layout самого приложения (шапка, сайдбар, сетка) на базе токенов
├── api.js                     — все обращения к бэку (fetch), один файл — один источник правды
│                                об адресах эндпоинтов
├── sampleData.js               — примерные данные (те же, что в 02_seed.sql), показываются,
│                                если бэк ещё не поднят — так фронт всегда выглядит "живым"
├── useApiResource.js          — общий хук: сходить за данными, при ошибке — откатиться на sampleData
│                                и явно показать баннер "бэкенд не отвечает"
├── components/
│   ├── Sidebar.jsx            — левая навигация (разделы как в мокапе)
│   ├── KpiCard.jsx            — карточка метрики на дашборде
│   ├── StatusTag.jsx          — цветной тег статуса документа (проведён/расхождение/…)
│   └── OfflineBanner.jsx      — баннер "показаны примерные данные"
├── pages/
│   ├── Dashboard.jsx          — обзор: счётчики + последние документы
│   ├── Products.jsx           — номенклатура (поиск, категория, цена, мин. остаток)
│   ├── Warehouses.jsx         — карточки складов
│   ├── Documents.jsx          — таблица документов (тип/склад раскрыты по названию, не id)
│   └── Counterparties.jsx     — таблица контрагентов
└── App.jsx                    — шапка + сайдбар + переключение экранов (без роутера — просто useState)
```

Запуск:
```bash
cd frontend
npm install
npm run dev
```

### `backend/`

Пустая папка — сюда ты кладёшь ASP.NET Core проект. Контракт, которого фронт ожидает, — в `docs/api-endpoints.md`. Строка подключения к БД — в `database/README.md`.

### `docs/`

- **`api-endpoints.md`** — полный список эндпоинтов, которые фронт дёргает: `/products`, `/warehouses`, `/stock`, `/documents` и т.д., плюс описание самой важной операции системы — `POST /documents/{id}/post` (проведение документа: как приход/расход/перемещение/инвентаризация должны менять `stock`). Это контракт для обсуждения, а не финальная спецификация — правь по ходу написания бэка.

### `design/`

Экспорт твоих UI-мокапов (кликабельный прототип на чертёжной эстетике). `ds/styles.css` оттуда уже скопирован в `frontend/src/styles/` и реально используется в коде — это не просто референс для галочки.

## Как всё это связано

```
design/ (мокапы, стиль)  ──> frontend/src/styles/design-system.css ──> frontend/ (реальный React)
                                                                              │
                                                                    fetch по контракту
                                                                              │
                                                                              ▼
                                                              docs/api-endpoints.md (контракт)
                                                                              │
                                                                              ▼
                                                    backend/ (C#, ASP.NET Core) ──> database/ (Postgres)
```

## Что дальше

1. Ты пишешь `backend/` под контракт из `docs/api-endpoints.md` (можно и нужно его менять по ходу).
2. Как только `GET /api/products` и остальные эндпоинты заработают на `http://localhost:5000` — фронт сам перестанет показывать баннер "бэкенд не отвечает" и начнёт показывать реальные данные, без единой правки кода (это и есть смысл `useApiResource`/`sampleData` — фронт уже готов к переключению).
3. Экраны создания/редактирования (новый документ, добавление товара и т.п.) в этом черновике не сделаны — это следующий шаг, когда определимся с формой `POST /documents`.
