# Складская система (курсовая)

Десктопное приложение для управления складом и товарными запасами.
Стек: **React** (фронт) + **C#/ASP.NET Core** (бэк) + **Avalonia UI** (десктоп-оболочка) + **PostgreSQL** (БД).
## Структура репозитория

```
Kursach/
├── database/     — SQL-схема и тестовые данные (готово, накатано в локальный Postgres)
├── frontend/     — React-приложение (черновик, реальный код, уже запускается)
├── backend/      — сюда ляжет C#/ASP.NET Core проект (пока пусто — твоя часть)
├── docs/         — контракт API и прочая документация для стыковки фронта с бэком
├── design/       — экспорт UI-мокапов (чертёжный/индустриальный стиль), взят за основу фронта
└── .claude/      — launch.json для запуска дев-сервера фронта через превью-инструмент
```

### `database/`

- **`01_schema.sql`** — DDL: 11 таблиц (справочники `roles`/`counterparty_types`/`document_types`, каталог `categories`/`products`, склады `warehouses`/`stock`, `users`, `counterparties`, документы `documents`/`document_items`). Все FK, CHECK-констрейнты (остаток не может быть отрицательным, `target_warehouse_id ≠ warehouse_id` и т.д.), индексы по внешним ключам.
- **`02_seed.sql`** — тестовые данные. Номенклатура, поставщики, покупатели и пользователи взяты из твоих UI-мокапов (`design/`), чтобы фронт-заглушки и реальная БД показывали одни и те же значения — так сразу видно, совпадает ли то, что рисует фронт, с тем, что лежит в базе.
- **`README.md`** — как поднять/пересоздать БД, строка подключения, и важное архитектурное решение: `stock` — это кэш остатков, который меняется **только** через проведение документов, а не редактируется напрямую.

БД уже создана и заполнена локально (`warehouse_db`, проверено через `psql`).

### `frontend/`

Vite + React (обычный JS, без TypeScript). Сейчас это осознанно минимальный черновик — одна страница, растёт вместе с эндпоинтами на бэке, а не собрана заранее целиком.

```
frontend/src/
├── App.jsx     — вся текущая страница: форма создания товара + список + удаление.
│                 Три места помечены TODO 1/2/3 — туда сам пишешь fetch к своим эндпоинтам
│                 (см. docs/frontend-integration-howto.md, там расписано, что куда).
├── index.css   — по паре строк на фон/цвет, стилизация будет наращиваться постепенно
└── main.jsx    — стандартный входной файл Vite, не трогали
```

Запуск:
```bash
cd frontend
npm install
npm run dev
```

### `backend/`

`backend/WarehouseApi/` — реальный ASP.NET Core проект (Minimal API + EF Core + Npgsql), пишется по ходу. На сейчас реализованы `GET/POST/PATCH/DELETE /api/products`. Строка подключения к БД — в `database/README.md` и в `appsettings.json` проекта.

### `docs/`

- **`api-endpoints.md`** — контракт-черновик: полный список эндпоинтов, которые фронт ожидает (`/products`, `/warehouses`, `/stock`, `/documents`...), плюс описание самой важной операции системы — `POST /documents/{id}/post` (проведение документа). Правится по ходу написания бэка, не финальная спецификация.
- **`frontend-integration-howto.md`** — пошаговая инструкция: что именно писать в каждом `TODO` в `App.jsx`, чтобы связать фронт с уже написанными эндпоинтами (без готового кода — только рецепт).

### `design/`

Экспорт твоих UI-мокапов (кликабельный прототип на чертёжной эстетике). `ds/styles.css` оттуда уже скопирован в `frontend/src/styles/` и реально используется в коде — это не просто референс для галочки.

## Как всё это связано

```
design/ (мокапы, стиль)  ──> frontend/src/styles/design-system.css ──> frontend/ (реальный React)
                                                                              │
                                                                    fetch по контракту
                                                                              │
                                                                              ▼
                                                              docs/api-endpoints.md (контракт)
                                                                              │
                                                                              ▼
                                                    backend/ (C#, ASP.NET Core) ──> database/ (Postgres)
```

## Что дальше

1. Бэк пишется по одному эндпоинту за раз (`backend/WarehouseApi`, сейчас на `http://localhost:5034`), контракт — `docs/api-endpoints.md`, правится по ходу.
2. Фронт растёт вслед за бэком: под новый эндпоинт — новый кусок `App.jsx` с `TODO`, который дописывается руками по `docs/frontend-integration-howto.md`.
3. Следующие документы/склады/контрагенты добавляются на фронт таким же образом, после того как появятся соответствующие эндпоинты.
