# Как связать черновой фронт с твоим бэком

В `frontend/src/App.jsx` три места помечены `TODO 1/2/3` — здесь описано, что именно туда написать. Код не даю целиком специально — только рецепт и то, на какие эндпоинты ориентироваться. Общий паттерн (fetch → await → проверка `response.ok` → `response.json()` → `setState`) — тот же самый, что в самой первой версии страницы, только теперь три раза с разными деталями.

## Перед началом — один блокер на бэке

Сейчас во всех моделях (`Models/Product.cs` и т.д.) стоит `[JsonIgnore]` над `Id`. Из-за этого `id` не приходит в JSON вообще — пока не убери эту аннотацию у `Id` в `Product.cs` (и остальных моделях, где понадобится `id`), ничего из трёх шагов ниже не будет работать: `p.id` в `products.map((p) => ...)` будет `undefined`, `handleDelete(p.id)` пошлёт `DELETE /api/products/undefined`.

## Общий рецепт (напоминание)

```js
async function делаетЧтоТо() {
  try {
    const response = await fetch(url, { /* опции */ });
    if (!response.ok) {
      throw new Error(`Ошибка сервера: ${response.status}`);
    }
    const data = await response.json(); // не для DELETE — там обычно пустой ответ
    // ... что-то сделать с data через set-функцию
  } catch (err) {
    // ... setError(err.message)
  }
}
```

## Шаг 1 — загрузить список (`useEffect`, TODO 1)

Эндпоинт: `GET {API_BASE}/products` (он у тебя уже есть и работает — ты его тестировал в самой первой версии страницы).

Что нужно сделать внутри `useEffect`:
1. Как и раньше — завести `async function load() { ... }` внутри эффекта и вызвать её (сам `useEffect` не может быть `async`).
2. `fetch` без второго аргумента — это обычный `GET`.
3. При успехе — `setProducts(data)`.
4. В `finally` (или в конце `try`, и в `catch`) — `setLoading(false)`, иначе надпись "Загрузка..." не исчезнет никогда (сейчас она висит вечно именно потому, что `TODO 1` пустой).
5. При ошибке — `setError(err.message)`.

Это почти буква в букву то, что было в самой первой версии `App.jsx` — отличие только в том, что переменная называется `products`, а не `data`, и добавляется `setLoading(false)`.

## Шаг 2 — создать товар (`handleCreate`, TODO 2)

Эндпоинт: `POST {API_BASE}/products`. Форма (`form` в состоянии) уже собирает нужные поля — сверься с `DTO/CreateProductRequest.cs` на бэке, какие поля он ждёт и как называются (JSON будет `camelCase`, то есть `categoryId`, а не `CategoryId`).

Что нужно сделать:
1. `fetch` теперь с объектом опций — обязательно три вещи:
   ```js
   fetch(`${API_BASE}/products`, {
     method: "POST",
     headers: { "Content-Type": "application/json" },
     body: JSON.stringify(form),
   })
   ```
2. Проверить `response.ok` (бэк вернёт `201 Created` при успехе — это тоже "ok").
3. `await response.json()` — бэк возвращает созданный товар (`Results.Created(..., product)`), с его настоящим `id` из базы.
4. Добавить этот товар в список: `setProducts((prev) => [...prev, created])` — `[...prev, created]` создаёт новый массив (React не увидит изменение, если мутировать `prev` напрямую, например через `.push`).
5. Не забудь очистить форму после успеха, если хочешь — `setForm({ sku: "", ... })`.

## Шаг 3 — удалить товар (`handleDelete`, TODO 3)

Эндпоинт: `DELETE {API_BASE}/products/{id}` — `id` уже приходит параметром в `handleDelete(id)` (вызывается как `handleDelete(p.id)` в таблице).

Что нужно сделать:
1. `fetch(`${API_BASE}/products/${id}`, { method: "DELETE" })`.
2. Проверить `response.ok`. У `DELETE` на бэке `Results.NoContent()` — это статус `204`, тело ответа **пустое**, поэтому `response.json()` здесь вызывать не нужно (упадёт с ошибкой парсинга).
3. После успеха убрать товар из списка без похода на сервер заново:
   ```js
   setProducts((prev) => prev.filter((p) => p.id !== id));
   ```

## Как проверять по ходу

- Открывай вкладку Network в дев-тулзах браузера — увидишь реальные запросы, их статусы и тела ответов.
- Если после фикса `[JsonIgnore]` и шага 1 список всё равно не появляется — проверь консоль браузера (там будет либо текст ошибки из `catch`, либо CORS-ошибка, как в прошлый раз).
- Если что-то не собирается или ведёт себя не так, как ожидаешь — присылай код или скриншот ошибки, разберём вместе, но сам код пишешь ты.
